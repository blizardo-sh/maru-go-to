# ADR-0015: Основной Canvas и совместимый React в одном кандидате

Дата: 2026-11-02. Статус: принято для локальной подготовки M8; production-выпуск отдельно.

## Контекст

Принятый Canvas зависел от приватной цепочки generated releases; старый root React не соответствовал опубликованным контрактам Б. Для переноса необходимо сохранить durable попытки, версии, owner/publication/CAS и отдельную IndexedDB каны.

## Решение

Перенести проверенную цепочку сервера/shared/React и подключённые Canvas-модули в обычные root sources. Использовать один Vite multipage artifact: index.html — Canvas, legacy.html — совместимый React из того же продолжения. Оба работают с одной API-реализацией и материалами. CLIENT_ENTRY выбирает entry aliases; прямой legacy.html остаётся доступным. Origin, профиль, auth namespace и storage keys сохраняются. Откат не восстанавливает БД.

Версионировать SHA-256 manifest всех исходников, материалов, runtime ассетов и dist. Release script сначала проверяет типы/пересобирает, затем фиксирует состав; повторное использование кандидата проверяет точный набор файлов, хеши и отсутствие symlinks. Приватные данные и лабораторные fixtures исключаются. Канонические публикации сверяются по content ID.

## Последствия

Обычные root build/start независимы от lab. React — ограниченный совместимый путь возврата, а не второй параллельный продукт. Смена контракта в дальнейшем требует повторной проверки обеих очередей/ACK/SQL и совместимости storage. Необязательный AUTH_COOKIE_PREFIX изолирует cookies локальных клонов, но одинаков у renderer одного origin. Исторические миграции перенесены; новой схемы/FSRS для M8 нет.

Аппаратные/слуховые M7-пункты остаются открыты. Контейнерная конфигурация подготовлена, запуск Docker/Caddy не проверен на этом Mac. См. verification/m8/M8.md и M8-matrix.md.
