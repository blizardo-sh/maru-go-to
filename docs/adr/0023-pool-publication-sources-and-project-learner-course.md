# ADR 0023: общий справочник источников и компактный курс для ученика

Статус: принято и реализовано 6 ноября 2026 по подтверждению пользователя после council.

Опубликованный курс остаётся неизменяемым JSONB-снимком в `content_publications`. Состояние ученика, ответы и расписание повторений остаются в существующих таблицах PostgreSQL. Отдельные реляционные таблицы для слов и источников не вводятся.

## Формат публикации 3

Один справочник `bundle.sourceRefs` содержит уникальные записи происхождения для всей публикации. Вложенные `sourceRefs` заменены массивами `sourceRefIds` с индексами этого справочника. После чтения сервер восстанавливает полный `Course`; алгоритмы обучения продолжают использовать прежнюю модель.

Справочник принадлежит конкретному снимку. Его индексы не являются постоянными ID между публикациями. Каноническое сравнение полей источника и упорядоченный обход ключей дают одинаковый результат при изменении порядка JSONB-ключей; порядок списков сохраняется. Проверяются форма записи, допустимость индекса, смешанные форматы, дубликаты справочника, глубина и объём раскрытия.

Новые пакеты выпускаются в формате 3. Чтение форматов 1 и 2 сохранено. SHA-256 считается по исходному снимку до раскрытия справочника. Миграция 0008 только расширяет ограничение `format_version`; существующие JSONB, ID и активный указатель не переписываются. Откат контента меняет активный указатель, а отложенный ответ продолжает обрабатываться по своей исходной публикации.

## Ответ клиенту

Для `GET /api/course` и `GET /api/bootstrap` новый клиент отправляет `X-Course-Representation: learner-v1`. Сервер возвращает привычную структуру `Course` с пустыми `sourceRefs` у слов, форм и отдельных значений, без служебного `sourceImports` и без уже объединённых `learning[].authored`. Это представление для обучения, не исходник для публикации и не вход редакторского валидатора.

Ссылки уроков и конструкций, тексты, примеры, задания, варианты ответов, каталоги, медиа и `publicationId` сохраняются. Полный снимок остаётся на сервере для проверки ответов и редакторской сверки. Проекция не меняет кешированный полный курс.

Без заголовка или при неизвестном значении сервер возвращает полный курс. Старый сервер также совместим с новым клиентом: он может проигнорировать заголовок и вернуть полный ответ. `Vary` разделяет варианты ответа; ETag курса вычисляется по фактическому телу, а клиентский кеш разделён по владельцу, публикации и представлению. Авторизация и проверка ожидаемого владельца выполняются перед выдачей 304. Bootstrap сохраняет `no-store`.

## Проверка и выпуск

Обратное раскрытие нового пакета полностью совпало с контентом предыдущего проверенного кандидата. Проверены форматы 1/2/3 в БД, личные словари двух владельцев, ETag/304, офлайн-ответы, откат и оба интерфейса. Замеры и конкретные артефакты находятся в `verification/marugoto-compact/REPORT.md`.

Перед будущей активацией формата 3 приложение должно уметь его читать и иметь миграцию 0008. Для отката к старому бинарному приложению сначала следует активировать совместимую публикацию формата 1/2. Автоматического преобразования новой публикации в старую или отката БД нет. Production в рамках этой реализации не менялся.
