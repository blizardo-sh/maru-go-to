# Хранить статистику тренажёра каны отдельно от словарного FSRS

30 октября 2026 года в Q30/Q32 пользователь выбрал самостоятельный тренажёр
хираганы и катаканы с направлениями «знак → чтение» и «чтение → знак», выбором
наборов и повтором ошибок внутри занятия. Статистика по знакам сохраняется
между занятиями отдельно для каждого ученика, без подключения к словарному
FSRS и прогрессу уроков: практика азбуки не создаёт словарные карточки и не
меняет прохождение Marugoto. Конкретное хранение определяется при реализации;
общие отображение и управление переиспользуются.

## Выбор хранения M5 — 1 ноября 2026

В локальном стенде статистика каны хранится в IndexedDB `japanese-kana-v1`.
Ключ счётчика включает владельца, азбуку, знак и направление. Счётчик попыток,
ошибок и последняя дата обновляются в одной транзакции с номером шага занятия
и квитанцией последней попытки. Повтор той же попытки возвращает квитанцию;
изменённый payload или устаревший номер шага отклоняются. Однозначный конфликт
устаревшего шага освобождает возможность начать новое занятие, не меняя статистику;
неоднозначный отказ хранилища сохраняет попытку для retry. Исходная попытка
сначала попадает в отдельный browser outbox; отказ хранилища не продвигает занятие.
Очередь упражнений остаётся в памяти; после reload можно начать новое занятие,
сохранив статистику и доставив неподтверждённый ответ.

Это минимальное сохраняемое представление для самостоятельного режима без
изменения SQL и словарных контрактов. Никакие словарные карточки, записи FSRS
или шаги Marugoto для каны не создаются. Цена этого выбора явная: данные доступны
только тому же профилю браузера на том же origin. Chrome и Safari, разные
профили/устройства и разные порты localhost не обмениваются этой статистикой.
Очистка данных сайта удаляет её; SQL-бэкап её не содержит. Перенос между
браузерами не реализован и не заявляется. При будущем требовании синхронизации
нужен отдельный серверный контракт с теми же владельцем и идентичностью попытки.
