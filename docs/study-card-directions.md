# Композиции учебной карточки: три прототипа

25–26 октября 2026. По снимку и запросу пользователя: разобрать текущие карточки, предложить несколько интерактивных направлений UX/UI. Реализация выбранного направления — последующий PR.

## Дерево решений

```text
Сравнение дизайна
├─ Материал: один набор настоящих слов и упражнений [подтверждено]
├─ Три направления [подтверждено, включая радикальное]
│  ├─ A: компактная доска, вопрос сверху, ответы 2×2
│  ├─ B: разворот, вопрос слева, ответы справа
│  └─ C: тихая мастерская, нейтральная поверхность, кот в окне
├─ Экраны для сравнения
│  ├─ Знакомство с группой слов
│  ├─ Перевод и аудирование: до ответа / верно / ошибка
│  ├─ Повторение: вопрос / раскрытие / свайп целой карточки
│  └─ Сборка фразы: черновик / проверка / правило
└─ После просмотра: выбор или сочетание элементов [открыто]
```

Ответ Q1: «Показать и более радикальный облик». Поэтому A/B сохраняют принятую комнату, бумагу и дерево; C пробует иной вес декора и навигации. Новый облик приложения пока не выбран. Макет не определяет правила обучения заново.

## Инвентаризация

- Marugoto Starter A1, русскоязычные начинающие ученики.
- Короткие части, знакомство группой до пяти слов, затем упражнения.
- Три направления слова: понимание текста, японский ответ, аудирование.
- Четыре сравнимых ответа; один правильный.
- Настройки каны, фуриганы и кандзи.
- Иллюстрации для знакомства и ответа; до проверки иллюстрация не подсказывает смысл.
- Сборка японской фразы из слов и частиц, правило по запросу.
- Отдельная бумажная карточка повторения: сначала тап, затем свайп.
- Рисованная комната, стол, бумага, деревянная рама и узнаваемый кот.
- Знакомство и повторение — разные учебные действия; личный прогресс должен сохраняться.

Идея: небольшое упражнение становится рабочей страницей личного японского учебника; в C этот учебник превращается в тихую мастерскую с окном и котом.

Вопрос экрана: «Как ответить на текущее задание?» Главные элементы — японское условие и варианты ответа, а не контейнер. Данные берутся через существующий `loadCourse`: словарь, примеры, формы и аудио. Демонстрационный счётчик относится только к четырём словам макета и не является прогрессом ученика.

## Кот с распорядком дня — 27 октября

Пользователь выбрал C2, отклонил отдельное окно кота и одобрил сравнение утра, дня и вечера. Вопрос макета: будет ли кот восприниматься обитателем общей комнаты, если менять его место и настроение в течение дня?

Концепция: ученик занимается за одним столом с котом; время суток меняет поведение спутника, а учебное задание остаётся устойчивым. Регистр — рисованные природные материалы, существующие дерево, бумага, рисунки и шрифты C2. Компоновка задания C сохранена; для общего стола выделена нижняя полоса и доска выровнена по центру. Отдельные окно и подпись кота убраны. Для ограниченного изменения компонента новый draw не нужен: приняты C2 и исходный лист C, seed 1917433948.

- Утро, 06:00–11:59: кот справа, активнее хвост и реакция на успех.
- День, 12:00–17:59: кот слева, спокойные движения головы и хвоста.
- Вечер, 18:00–05:59: кот справа, лежит; во время аудио приподнимается, отклики с небольшой амплитудой.
- «По местному времени» выбирает состояние по часам устройства при входе. Внутри текущей попытки часовой переход ничего не переключает.

Токены компонента: C2 сохраняет цветовые роли; десктопная фигура 220 px, стол 184 px; планшет 164/156 px; телефон 120/112 px, короткий экран 84/78 px. Сетка — одна колонка задания до 918 px и отдельная нижняя полоса общего стола. Геометрия доски одинакова для всех трёх периодов. Кот свободно располагается слева или справа в отведённой полосе, кнопки и свайп остаются доступны.

Единственный новый выразительный момент — перемещение по общему столу. Триггер в макете: выбор периода или кнопка «Место»; существующее задание и черновик сохраняются. Фазы: исходное место → перемещение с небольшим покачиванием → новая опора. Длительность 1000 ms, вечером 1300 ms, easing cubic-bezier(.45,0,.2,1), только transform. Прототип использует существующие сидячие позы: это проверка места и траектории, не готовая анимация ходьбы. Для полноценной ходьбы потребуются отдельные кадры. На телефоне используется тот же безопасный нижний ряд. Reduced motion меняет место без перемещения; ответ и эмоция остаются видимы. В первые три секунды кот уже виден, появления и заставки нет.

Спокойное ожидание, моргание, прослушивание, успех и ошибка используют прежний Cat. Направление взгляда при свайпе задаётся только в макете, без изменения GestureCard. Нет новых звуков: учебное аудио и выбранные ранее настройки не подменяются. Фигура не размонтируется при смене периода. Локальные ответы, открытый экран, фуригана и черновик не зависят от места кота.

Запуск прежний: `bun run prototype:study-cards`; ссылка `?prototype=study-cards&variant=C&skin=wood&cat=daily&daypart=morning|day|evening|auto`. Другие направления и прежний C2 без `cat=daily` остаются доступными для сравнения. Все изменения в draft PR #28; публикация на рабочем сервере и перенос в production не входят в макет.
