# Выпуск на имеющемся VPS

Основа принята пользователем: Hono + Bun, PostgreSQL, без брокера. Версии и образы закреплены в [toolchain.json](../deployment/toolchain.json), npm-версии — в [reference manifest](../verification/stack/package.json) и lockfile. Сервер не подключался и развёртывание не выполнялось; [локальная проверка](STACK-COMPATIBILITY.md) не заменяет Linux/VPS-проверки.

## Состав

Три службы Docker Compose: Caddy 2.11.7, Bun 1.4.3 API и PostgreSQL 18.6. Docker Engine 29.9.1, Compose 5.6.0. Caddy обслуживает Vite `dist` и направляет `/api` в backend; PostgreSQL доступен только во внутренней сети Compose. Постоянные каталоги БД, TLS-состояния Caddy, секретов и резервных копий находятся вне заменяемых образов. Redis, брокер, отдельный worker и локальная LLM в исходную поставку не входят.

Для PostgreSQL 18 volume монтируется в `/var/lib/postgresql`, PGDATA — `/var/lib/postgresql/18/docker`. Major-upgrade PostgreSQL требует отдельного плана, а не замены major-tag поверх старого каталога.

## До установки

При наличии разрешённого доступа проверить фактическую ОС, архитектуру CPU, свободную RAM/диск, службы, занятые порты и существующие данные. Исходный профиль сообщает Ubuntu 22.04 / 1 vCPU / 2 GB / 20 GB без GPU, но не свободные ресурсы. Проверить домен, DNS и доступность HTTPS; сторонние действующие службы сохраняются.

## Сборка и проверка

1. Создать реальную структуру приложения с закреплёнными версиями и isolated linker. Выполнить frozen install; target Linux/CPU совпадает с VPS. Зависимости устанавливаются внутри Linux build stage.
2. Выполнить typecheck TypeScript 7.0.2, тесты правил, интеграции на `postgres:18.6-bookworm`, Vite build и Playwright. Вызов Vite должен исполняться Bun (`bun --bun`).
3. Собрать API на базе `oven/bun:1.4.3-slim` и статический frontend вне VPS. API-поставка включает production-зависимости, корпус и SQL-миграции. При переносе isolated installation сохраняется весь `node_modules/.bun` и относительные ссылки.
4. Проверить запуск готового образа, вход, чтение корпуса и БД. Зафиксировать version/tag и digest для целевой архитектуры. Секреты передаются окружением/защищёнными файлами, в образы и frontend они не включаются.

CI-среда — Ubuntu 24.04, Bun 1.4.3, Node 24.22.0 для browser tooling; action версии и SHA заданы в manifest. [ci.example.yaml](../verification/stack/ci.example.yaml) проверяет compatibility-пакет; после реализации к нему добавляются проверки приложения. Этот workflow в текущем сеансе не запускался.

## Обновление

Перед сменой схемы обеспечить пригодную резервную копию. Миграции генерируются Drizzle Kit, проверяются как SQL и выполняются управляемым отдельным шагом. При запуске обычный backend не получает обязанности самопроизвольно менять схему.

Обновление образа не пересоздаёт данные. Сначала проверяется совместимость схемы и предыдущей версии API; откат приложения не объявляется автоматическим откатом БД. Readiness подтверждает доступность нужной схемы, health не раскрывает данные или секреты. SIGTERM прекращает приём работы, затем ограниченно дожидается активных запросов и закрывает pool; период graceful stop контейнера превышает этот бюджет.

## Проверки на сервере

- Учебные упражнения, словарь и синхронизация работают при недоступности ИИ.
- Прямая регистрация без приглашения закрыта; одноразовые ссылки и срок действия проверены; данные двух пользователей изолированы.
- Повтор запроса после commit не дублирует историю; два устройства обновляют одну версию расписания один раз.
- При 10 одновременно занимающихся измерены RSS/CPU, подключения PostgreSQL, диск, p95 и ошибки обычного API отдельно от ИИ. Лимиты провайдера проверены независимо от ресурсов VPS.
- После обновления и восстановления на отдельной копии сохранён прогресс; измерены размер и длительность backup, объём WAL/логов/истории и время восстановления.

## Резервное копирование и ресурсы

Копии должны находиться также вне исходного VPS; пригодность подтверждается восстановлением. RPO ≤ 1 час и RTO ≤ 4 часа после обнаружения аварии остаются предложением Q36, пользователь их пока не подтвердил. Место, периодичность, срок хранения, шифрование и оповещение о пропуске backup фиксируются при согласовании этой политики; платное хранилище не подключалось.

Достаточность 2 GB RAM не подтверждена. Начальная конфигурация pool/лимитов измеряется на выбранных образах; расширение обосновывается памятью, CPU, ошибками и задержками целевого сценария. Несколько контейнеров на одном VPS не создают отказоустойчивость к потере самого VPS. Размер сервера для собственной модели ИИ рассматривается отдельно от web-нагрузки.
