`Review` означает локально готово к проверке; `Merged` не используется: merge,
commit, push и PR не выполнялись. Новые изменения зависят от прежнего dirty/untracked
визуального задела, поэтому его нельзя безопасно включить в собственный коммит.
Исходное состояние сохранено отдельно; исторические публичные отчёты восстановлены
побайтно после регрессии, новые результаты имеют собственные M4 имена.

Ворота: тесты → review → аудит границ/секретов → визуальная проверка и документация.
Ошибки из ревью исправлялись интегратором; автоматическая проверка запретила
тестовую запись существующим учеником в work. Вместо неё выполнен разрешённый
сценарий новым синтетическим профилем в отдельном клоне baseline. Прежние профили,
рабочий клон и baseline сохранены; неподтверждённые ручные проверки явно открыты.

Новые shared skills не создавались: однократный локальный серверный patch и
проверки не обосновывают новый универсальный harness или UI framework.
