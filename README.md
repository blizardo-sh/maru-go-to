# Японский: тренажёр к очным занятиям

Онлайн-приложение для нескольких учеников по Marugoto Starter A1: выбор материала всех 18 уроков, словарные карточки в двух направлениях, аудирование, конструктор предложений, личные списки и свободный разбор. У каждого ученика отдельные настройки и прогресс. Вход только по одноразовым приглашениям.

Производственный HTTPS и все три контейнера проверены 21 октября 2026 года. В CI проходят 77 тестов на PostgreSQL 18.6, браузерный вход и Linux-образы с реальным защищённым профилем. Внешняя зашифрованная копия восстановлена в отдельную БД; публичные проверки доступа и безопасности описаны в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Локальный запуск

Нужны Bun 1.4.3 и отдельная PostgreSQL. Версии зависимостей закреплены в `bun.lock`; `verification/stack` хранит исходный compatibility-probe.

```sh
bun install --frozen-lockfile
cp .env.example .env
```

В `.env` задайте `DATABASE_URL`, случайный `BETTER_AUTH_SECRET` минимум из 32 символов и `APP_URL=http://127.0.0.1:5173`. Используйте отдельную базу, затем выполните:

```sh
bun run db:migrate
bun run admin bootstrap your-email@example.com
bun run dev
```

В другом терминале запустите `bun run dev:client` и откройте [локальное приложение](http://127.0.0.1:5173). Команда `bootstrap` печатает одноразовую ссылку: первый зарегистрированный по ней пользователь становится администратором и сам задаёт пароль. Открытая регистрация закрыта. Администратор выдаёт следующие приглашения и ссылки восстановления через приложение. Из доверенной серверной консоли доступны также `bun run admin invite email` и `bun run admin recovery email`. Ссылки не отправляются автоматически; токен расположен во фрагменте URL.

API работает на `127.0.0.1:3000`, Vite проксирует `/api` с одного origin. `/health` проверяет процесс, `/ready` — доступность схемы базы и корпуса. Авторизованному пользователю доступен контракт `/api/openapi.json`.

Все последующие изменения отправляются отдельной feature-веткой и принимаются через Pull Request в `main`.

## Проверки

```sh
bun run typecheck
bun test tests
bun run build
```

Интеграционные проверки требуют одноразовую локальную базу с именем `japanese_app_test`, применённые миграции и переменные `TEST_DATABASE_URL` и `JAPANESE_INTEGRATION_DATABASE_URL`, указывающие на неё. Без этих переменных соответствующие DB-проверки явно пропускаются. Обычная пользовательская база для тестов не используется. Проверка подготовительных файлов: `python3 scripts/verify_preparation.py`.

Самостоятельные browser-runner сохраняют новые отчёты и снимки в игнорируемую Git папку `test-results/` внутри проекта. Команды и границы прежних проверок — в [VERIFICATION.md](docs/VERIFICATION.md).

## Самостоятельное размещение

Производственный адрес: https://outboundserver.freemyip.com/ — HTTPS без номера порта; VPN и OpenGym продолжают использовать прежние адреса. Nginx на VPS завершает TLS, Caddy обслуживает собранный интерфейс, API и PostgreSQL доступны только внутри Compose.

Workflow [Delivery](.github/workflows/delivery.yml) проверяет каждый PR: frozen install, типы, уязвимости зависимостей, миграции и тесты на отдельной PostgreSQL, сборку и браузерный вход по приглашению. После принятия в `main` GitHub собирает Linux-образы и отправляет их в GHCR; отдельный SSH-ключ разрешает только выпуск конкретного коммита. Сервер закрепляет digest образов, создаёт внешнюю копию до миграции, проверяет readiness и восстановление после выпуска.

Копии шифруются restic и хранятся на втором сервере: часовые за неделю, ежедневные за месяц. Запуск каждые 30 минут оставляет запас для целевого RPO ≤ 1 час; восстановление проверяется ежедневно на отдельной базе. Цель RTO ≤ 4 часа принята, но полный перенос на новый VPS требует отдельного учения. Команды, первоначальная установка, откат и границы проверки — в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

Свободный разбор сопоставляет подготовленные примеры и словарь. Для других фраз можно настроить OpenAI-совместимый сервис через `ANALYSIS_URL`, `ANALYSIS_MODEL`, при необходимости `ANALYSIS_API_KEY`; он включается только при явном `ANALYSIS_FREE_ONLY=true`. Эта настройка требует проверки условий выбранного сервиса оператором и не является доказательством бесплатной квоты. При ошибке или исчерпании квоты другой или платный сервис автоматически не вызывается. Качество внешнего провайдера по [контрольному набору](docs/AI-EVALUATION.md) пока не измерено.

## Что уже принято

Собственный VPS в Амстердаме; до 100 аккаунтов / 10 одновременно занимающихся; email/пароль, ручные одноразовые приглашения и восстановление; личные данные; общий прогресс между устройствами; весь Starter A1 с расширением; общее занятие с автоматическим чередованием конструкций, двух направлений словаря и аудирования; свободный разбор внутри упражнения с независимыми фильтрами; три вида написания с фуриганой по умолчанию; уютный кот-помощник. Смена вида сохраняет расписание. При недоступности бесплатного ИИ оплата автоматически не включается.

Техническая основа: Hono + Bun, PostgreSQL, без брокера. Конкретные frontend/auth/ORM/test-инструменты и pins перечислены в архитектуре и матрице совместимости; цели восстановления Q36 приняты 21 октября 2026 года.

## Проверка файлов

Из корня: `python3 scripts/verify_preparation.py`. Проверяются карта курса, манифест источников, формы и задания образца, PNG и внутренние ссылки. Пройденная проверка этих файлов не означает пройденную приёмку приложения или ИИ.

Библиотечные проверки запускаются отдельно по [инструкции probe](verification/stack/README.md). Исходный compatibility-probe локально проходил восемь проверок с PostgreSQL 18.4. Текущее приложение дополнительно проверено в GitHub CI на PostgreSQL 18.6/Linux и развёрнуто на VPS; прежние ограничения probe не описывают состояние production.

## Границы готовности

Рабочая версия и корпус всех 18 уроков реализованы. Исходная лексика извлечена из официальных русских указателей; авторские объяснения и упражнения сохраняют отдельные статусы независимой языковой проверки. Статическое японское аудио подготовлено отдельно от корпуса; шаблонные записи без конкретного произношения не выдаются как готовые задания на слух. Linux-контейнеры, PostgreSQL 18.6 и восстановление внешнего dump проверены. Нагрузка 10 учеников, полное восстановление нового VPS и качество внешнего ИИ требуют отдельных испытаний. Локальная Qwen3-8B на исходный VPS 1 vCPU / 2 GB / 20 GB без GPU не закладывается.
