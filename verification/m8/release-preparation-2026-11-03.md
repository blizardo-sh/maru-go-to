## Council: один PR или разделение

- **Architect:** оставить единый принятый снимок с обязательным CI. Причины: пользователь принял эту комбинацию; изменения main сохранены; новые промежуточные версии после разделения не проверены. Риск — старые DOM-тесты сами по себе не доказывают работу Canvas.
- **Skeptic:** «Дробить PR сейчас не стоит, но зелёного CI недостаточно для автоматического перехода в ready». Нужны карта изменений и проверка результата после main; существующий backup не доказывает качество миграции.
- **Pragmatist:** «сохранить один PR №29 и перевести его в ready после зелёного CI». Разделение увеличит повторную проверку без очевидного снижения риска; ограничение React/Canvas нужно показать рецензенту.
- **Critic:** «оставить один PR» и проверить Canvas на итоговом коммите. Тысячи вариантов раскладки не доказывают сохранение, ввод и загрузку публикации.

Итог: один PR. Сильнейшее возражение — CI совместимого клиента не заменяет Canvas smoke — принято: карта и отдельный браузерный сценарий добавлены. Слияние PR и выпуск на production остаются отдельными действиями.
