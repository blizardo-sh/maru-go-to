## Вход и запуск

Для двух скопированных профилей подготовлены отдельные пароли **только рабочего
клона**. Адреса/ID учеников сохранены. Данные входа находятся в приватном файле
`.local/rehearsal-20261028/Вход в локальную копию.txt`. Рабочие пароли на сервере
не менялись. Сессии стенда используют новый секрет и префикс cookie `pixi-stand.`;
cookie других локальных приложений в API не передаются. Сервер принимает только
`localhost:5191` и проверяет разрешённый Origin.

Уже восстановленный клон используется повторно. **Не запускайте восстановление
или подготовку паролей повторно ради обычного запуска.** `rehearsal-restore.py`
откажется заменять существующий `runtime.json`.

Из папки `verification/pixi-ui-lab`, при работающем локальном PostgreSQL:

```sh
npm run build
/private/tmp/japanese-stack-toolchain-1.4.3/bun rehearsal-server.mts
```

Нужен Bun 1.4.3. Указанный путь — установленный для этого рабочего места инструмент;
после очистки `/tmp` используйте установленный Bun этой версии. Для остановки
сервера — Ctrl+C. Кластер управляется `pg_ctl` из `.local/tools/postgres18/bin/`;
его каталог — `.local/rehearsal-20261028/postgres`. Сам сервер базу не восстанавливает,
не мигрирует и не сбрасывает. Проверка имени БД/loopback запрещает случайный запуск
этого runner против рабочего сервера.

## Реальное взаимодействие

Вход, выбор урока, знакомство, аудио, задания, конструктор, видеокадр и итог
используют серверные данные. Видимый интерфейс нарисован PixiJS; нативные поля
обслуживают ввод/пароли/доступность, видеокадр использует согласованное исключение.
Открытый урок закреплён за своей публикацией. После подтверждения ответа следующая
карточка получает соответствующую новую публикацию, если сервер перевёл маршрут.

Первый выбор отправляется сразу через неизменённый транспорт b378: исходный
`attemptId` записывается в очередь браузера до POST. После ошибки можно исправить
выбор; исправление остаётся локальным и не создаёт второй оценки. Правильный
вариант заранее не выделяется. Через 1,2 секунды после верного выбора выполняется
переход, его можно остановить. Во время сохранения карточка и кнопки остаются на
месте; действия недоступны до подтверждения. Незавершённый маршрут продолжается
после перезагрузки. Кнопки сброса настоящего прогресса нет.

Подготовленный конструктор использует исходные ID токенов и серверную проверку;
незавершённый черновик не оценивается. Свободный японский ввод — отдельный анализ
без зачёта исходного навыка. Внешний AI-провайдер в стенде отключён: подготовленные
фразы проверяет сервер, неизвестные фразы получают явно обозначенный локальный образец.

Старый клиент **того же выпуска** доступен на `/legacy.html`: он использует этот же
локальный API, cookie и очередь. Внешние медиа разрешаются сначала из копии корпуса,
затем из публичных файлов соответствующего выпуска; отсутствующие файлы дают 404.
Используется CSP из существующей конфигурации приложения.

## Проверки и границы

[Обезличенный отчёт](checks-connected-2026-10-28.json) фиксирует восстановление,
сохранность и проверки браузера. Все изменения обучения при проверках принадлежат
одному локальному профилю: урок 1 пройден; урок 2 использован для конфликтов и задержки.
Прежняя история попыток неизменна, остальные ученики и прежние маршруты сохранены.
Результаты сравнения API используют общий момент времени для due и один UTC-день
для today; порядок множеств освоенных слов не считается изменением прогресса.

Команды (из папки стенда):

```sh
npm run typecheck
/private/tmp/japanese-stack-toolchain-1.4.3/bun lesson-flow-check.mjs
/private/tmp/japanese-stack-toolchain-1.4.3/bun connected-flow-check.mts
/private/tmp/japanese-stack-toolchain-1.4.3/bun rehearsal-verify.mts
node input-focus-check.mjs
node stand-fit-check.mjs
/private/tmp/japanese-stack-toolchain-1.4.3/bun stand-content-check.mts
```

`connected-check.mjs`, `connected-protocol-check.mts` и `connected-wait-check.mjs`
— **сценарии с записью только в рабочий клон**, использованные по порядку при первой
репетиции. Они не сбрасывают завершённый урок для повторного прогона. Обычные
разрушительные fixture-suite с БД `japanese_app_test` к этой копии не подключались.

Для Safari WebDriver выделен порт **5192**; 5191 занят API стенда:

```sh
/usr/bin/safaridriver -p 5192
node connected-safari-check.mjs
```

Safari должен быть на переднем плане: скрытое окно останавливает requestAnimationFrame.
Этот сценарий проверяет вход, доступные кнопки через Enter и продолжение существующего
урока без записи ответов. Он не заменяет реальный японский IME, iPhone/Android,
VoiceOver/TalkBack, менеджер паролей и проверку мыши в Safari.

В полном старом `paper-check.mjs` прошли четыре размера Chrome и интерактивные
проверки до внешнего видео; ожидание кадра официального ролика завершилось таймаутом.
HTTP HEAD и Range вернули 200/206, CSP-нарушений не было. Фактическое воспроизведение
ролика в этой повторной проверке не подтверждено; урок разрешает его пропустить.
Это не объявляется успешным полным видеопрогоном. Стойка пока не заменяет все
разделы приложения: обычное повторение, личные списки, настройки и управление
доступом остаются следующими этапами миграции.

## Отдельное сравнение закрепления — 29 октября

`http://localhost:5191/paper.html?study=compare` использует публичный учебный пример,
без профиля и API. Два сценария сравнивают текущий выбор и вспоминание/подсказки;
повтор ошибок использует `advanceDeck` закреплённого выпуска. Результаты хранятся
только в памяти и не меняют FSRS или оценки подключённого урока.

Шапка вынесена на деревянные таблички над стойкой. В начале и итоге урока, а также
словарных заданиях материал помещается без внутренней прокрутки; на маленьких
экранах подробности знакомства разделены на смысловые вкладки.
