# Canvas UI lab — throwaway M1/M2 prototype

Отдельный стенд для проверки PixiJS 8.22.0 и сравнения трёх композиций карточек.
Ветка: `prototype/pixi-ui-lab`, исходный срез плана: `481648f`.
Основной клиент, сервер, зависимости приложения, база и пользовательский прогресс не меняются.
Стенд не вызывает API; `/api/*` специально возвращает 404. Состояние — только в памяти.

**Дизайн A/B/C отклонён пользователем 27 октября:** слишком простые формы,
серые прямоугольники, полосы и недостаточная художественная проработка.
Эти маршруты сохраняются как технические образцы, не как одобренный дизайн.
Новый [визуальный эскиз v2](art-direction/paper-card-study-v2.png) находится на согласовании;
это растровая иллюстрация направления, ещё не интерактивный Canvas-экран.

## Запуск

Из корня репозитория при установленных зависимостях проекта:

```sh
npm --prefix verification/pixi-ui-lab ci
npm --prefix verification/pixi-ui-lab start
```

Собранный клиент работает на [127.0.0.1:5190](http://127.0.0.1:5190/).
Сервер берёт CSP непосредственно из `deployment/nginx-http.conf` и обслуживает
существующие публичные ассеты без копирования. Vite dev server в этой проверке не используется.

## Что смотреть

- [Технический стенд](http://127.0.0.1:5190/?view=lab): две реализации фуриганы,
  ввод/выделение/пароль, официальный ролик, отчёт CSP и потеря/восстановление WebGL.
- [A — карточка/колода](http://127.0.0.1:5190/?variant=A): один бумажный объект с вопросом и ответами.
- [B — разворот альбома](http://127.0.0.1:5190/?variant=B): задание и рабочая страница рядом;
  на телефоне страницы идут друг под другом.
- [C — вопрос и ответы](http://127.0.0.1:5190/?variant=C): отдельная крупная область вопроса
  и отдельная рабочая панель.

Кнопки «Слово» и «Фраза» меняют упражнение. Нижние стрелки и ← → меняют композицию
с сохранением текущего ответа. Стрелки в поле ввода остаются у редактора.
«Комната» переключает пять ранее одобренных фонов. Камера неподвижна.
Кнопки и фокус рисуются в Canvas; невидимые DOM-элементы обслуживают клавиатуру и доступность.
При ошибке графики появляется разрешённый нативный экран восстановления.

Слово и фраза взяты из материалов репозитория: «魚／さかな», другие слова курса
и «わたしはがくせいです。». `fixtures.json` содержит происхождение и SHA-256 курса.
Локальная проверка фразы служит только сравнению взаимодействия; это не замена
настоящему оцениванию, FSRS или механизму сохранения.

## Повторяемые проверки

При запущенном сервере:

```sh
npm --prefix verification/pixi-ui-lab run typecheck
npm --prefix verification/pixi-ui-lab run build
npm --prefix verification/pixi-ui-lab run check
```

Проверка использует установленный Google Chrome и Playwright WebKit из зависимостей
основного проекта. Если WebKit отсутствует:

```sh
node node_modules/@playwright/test/cli.js install webkit
```

`check.mjs` проверяет источник фикстур, точное совпадение CSP, отсутствие API-запросов,
геометрию фуриганы/кнопок, редактирование японского текста, синтетические composition-события,
клавиатурный ответ, сохранение состояния вариантов, официальный MP4 и восстановление WebGL.
Матрица: A/B/C × слово/фраза × 1440×1000, 1280×900, 768×1024, 390×844, 320×640,
844×390 в двух движках. Карточка не должна перекрывать кота; на узком экране он ниже задания.
Снимки и машинный отчёт сохраняются в игнорируемую `test-results/`.
Для повторной проверки только технической части: `npm --prefix verification/pixi-ui-lab run check -- --technical-only`.

Настоящий Safari проверяется без Selenium и дополнительных зависимостей: сначала
включить автоматизацию в настройках Safari, затем запустить `/usr/bin/safaridriver -p 5191`
и в другом терминале `node verification/pixi-ui-lab/safari-check.mjs`.
Скрипт создаёт и закрывает отдельное окно автоматизации. Safari проверяется
клавиатурой через невидимые доступные кнопки: pointer-координаты WebDriver
при текущем масштабе страницы смещались. Мышь Safari требует отдельной ручной проверки.
Фактические размеры окна/viewport записываются в отчёт; узкое окно Mac не считается iPhone.

Итоги и открытые ручные проверки: [RESULTS.md](RESULTS.md).

## Обязательная ручная приёмка

Playwright WebKit не заменяет Safari и физический iPhone. Эмуляция размеров не открывает
настоящую системную клавиатуру и не проверяет кандидаты японского IME.

1. **Safari на Mac:** открыть стенд, сравнить обе фуриганы и длинную строку; ввести японский
   текст через настоящий IME, выбрать кандидата, исправить середину и вставить несколько строк.
   Проверить Tab/Shift+Tab, видимый фокус и ответ Enter. Автоматизация Safari требует
   включённого пользователем Settings → Developer → Allow remote automation.
2. **iPhone Safari и Android Chrome:** повторить ввод с открытой клавиатурой, выделение,
   исправление/вставку, поворот в обе стороны; поле и нужные кнопки должны оставаться достижимыми.
   Проверить масштабирование и читаемость фуриганы на Retina.
3. **Видео:** нажать «Проверить», затем паузу/просмотр и +5 секунд. Кадр должен оставаться inline,
   кнопки — Canvas. При переходе к карточкам и сворачивании страницы ролик останавливается.
   Проверен один официальный ролик; остальные 79 требуют отдельной сверки.
4. **VoiceOver/TalkBack:** задание, поле, порядок управления, статусы результата и восстановление.
   Скрытое правильное решение нельзя выдавать до ответа. Японская речь должна читаться корректно.
5. **Пароли:** использовать только пробные данные. Сейчас проверяется маскирование нативного поля;
   полноценные формы входа/регистрации/восстановления и менеджеры паролей ещё не перенесены.
6. **Графика:** ввести текст, запустить «Проверить восстановление» и «Повторить запуск»;
   ответ и черновик должны сохраниться. Реальную нехватку памяти/выгрузку вкладки проверить отдельно.

Окончательный выбор композиции и жестов остаётся за пользователем. Эти прототипы
не закрывают весь M1 и не разрешают массовый перенос/выпуск до ручных проверок.
